PRAMAN / प्रमाण — evidence

AI writes the code. PRAMAN checks that it actually works — running authored browser and command checks against real software, applying strict proof gates, and returning evidence instead of a confident summary.

The problem

Writing code is no longer the bottleneck. Proving it works is.

A clean build, a passing unit test and a confident AI summary can all hide a broken screen, a wrong value, or a fix that only removes the symptom. Agents need somewhere to exercise the software and a way to bring back evidence.

The agent writes

Claude Code, Codex, OpenCode, Cursor or Kiro implements and repairs the software, using its own tools and models.

PRAMAN executes

Authored browser scenarios and trusted command declarations run in fresh sessions against the real app, with declared requirements checked.

Evidence comes back

Passed, failed or insufficient evidence — with proof/spec hashes, screenshots, outputs and a report an agent can act on.

Run it

Source, one command at a time

# from the public repository
npm ci
npm run build
npx playwright install chromium
node examples/first-use/run.mjs

# then point it at your own project
node dist/cli.js scenario-verify scenario.json -o .praman/run
node dist/cli.js command-verify commands.json -o .praman/run

Interfaces

  1. Browser verification — authored steps and checks in real Chromium, 2–10 fresh repeats, screenshots and network evidence.
  2. Command verification — trusted executables with explicit exit, output and bounded artifact expectations.
  3. Three modes — acceptance, historical repair and explicit comparison. Missing evidence is never green.
  4. MCP server — the same engines over stdio, so a coding agent can ask for evidence.

How Kiro was used

Kiro was genuinely used, but narrowly. One bounded Kiro IDE session (86 minutes, recorded spec session, real tool calls) worked on a Headlamp dry-run feature before the monthly usage limit ended it. An AI coding assistant completed the remaining work and built PRAMAN's core — the write-up says exactly that, and does not claim Kiro built the product.

  • Spec-first session — Kiro spec artifacts and spec-session mapping are recorded.
  • Honest attribution — mixed authorship disclosed; PRAMAN core is not Kiro-authored.
  • Repo artifacts — /.kiro specs, steering, hook and custom agent are tracked in the repository.

Limits — what this is not

  • Not a sandbox. Trusted commands and browser actions run with your user's authority; PRAMAN does not contain hostile code.
  • Not autonomous test design. Checks are authored; PRAMAN verifies declared requirements, not whole-application correctness.
  • Not validated off this host. Same-host evidence only so far; CI is configured and independent-machine validation is still pending.
  • No hosted service. It runs from source; there is no public endpoint and no published package.
